# どんぐりの夢 共有ボード

ハンドメイド活動「どんぐりの夢」（あみぐるみ等の展示・販売）の共有ボード。公開資料をGitHub Pagesで表示し、私的な記録・出店準備はLINE認証済みAPIで扱う。

## 構成

- `index.html` / `board.js` / `workflow.js`：出店／作品・在庫／売り場／やることの4分類。出店内は準備・当日・振り返りを切替。売り場にポップ・ブースを集約し、資料に以前の作業案を保管
- `events.json`：既存9出店の識別子・名称。非公開記録の関連付けをサーバー側で検証
- `event.html` / `event.js` / `event.css`：新しい非公開出店の作成と、出店ごとの持参作品・使用ポップ・準備メモ
- `event-board.js`：認証済みの出店を一覧に追加。認証喪失時は名称・会場も消去
- `pops.json`：既存12ポップの識別子・名称。選択保存の検証用
- `backend/events.js` / `backend/events-schema.sql`：出店準備の保存・競合検知・変更前の履歴
- `assets/`：写真とポップの画像
- `gallery.js` / `gallery.css` / `gallery.json`：出店タブと作品・在庫タブに追加写真を統合。作品・個人依頼・個人作品・贈り物・出店写真を分類し、検索・拡大を用意。旧 `gallery.html` のリンクはボード内の写真へ移動。開催回が不明な写真を既存イベントIDに自動で紐付けない
- `work-collections.js`：作品／個人依頼／個人作品／贈り物の切替と分類横断検索。出店写真は対応する既存の出店ページへ追加し、未登録の開催回は出店情報の枠を設ける。[配置と保全](docs/works-event-organization.md)を参照
- `icon.webp`：アイコン
- `context-comments.js`：私的な記録・出店準備の対象別コメントとAI依頼への導線
- `comments-config.js` / `comments-api.js`：LINE内のコメント共有接続
- `backend/`：非公開DBへ接続するWorkerのコードと設定例
- `docs/comments-setup.md`：共有設定・配備前の確認手順
- `private.html` / `private.js` / `private.css`：二人の振り返り・売上・やること・棚卸・写真確認・更新依頼
- `catalog.json`：27作品と登録写真の対応。うち10件は販売候補から除外・作品やポップへ統合して参考保管。写真点数や在庫実数を入れない
- `docs/source-reconciliation.md`：更新シートと既存ページの差分・確認待ち

## 編集の進め方

- 編集は人でもAI（Claude Code、Codex、ChatGPT等）でも同じ手順で行う。画面は `index.html`、動作は `board.js` 等、見た目はCSS、画像は `assets/` を編集し、`main` ブランチへプッシュすると、数分で GitHub Pages へ自動反映される
- 作品・イベント・ポップの内容の正本は、別に運用している更新シート（Googleスプレッドシート）側の記入内容とする。シートで変更された内容をこのページへ反映する運用

## 編集ルール

- 文面は言い切り形にする。丁寧語（です・ます）と「だ」「である」で終わる文は使わない
- 全コーナーに対象別コメント導線を設ける。写真は一枚ごと、作品・出店・ポップ・売り場の図や工夫・資料の作業は各項目ごとに設け、一覧全体のコメントだけで代替しない。新規コーナー追加時も必須。固定の `data-comment-key` と公開ラベルを設定し、`comment-coverage.js` と既存の共通保存・認証・IME保護を使用。表示名・並び順を変えてもキーを変えず、既存キーは移行・削除しない。追加時と公開前に `npm run check:comments` を実行。[コメント対象の実装規則](docs/comment-corners.md) を参照
- 文面は本人・妻の行動（やること・したこと）で書く。AIの所感は書かない
- イベント名は末尾に開催年月を「（YYYY年M月）」の形で付ける
- 価格・日程・場所は確認できたものだけを書く。未確認のものは「未確認」と明記し、推測で埋めない
- 終わったイベントは新しい順に並べる
- 画像は長辺1080px・JPEG品質80を目安に圧縮してから `assets/` へ追加する
- 作品の写真は実物写真と本人のポップ原画を使う。生成イラストは使わない（ポップのイラスト版として作成済みのものは除く）
- ページ全体の背景は淡い生成り（#faf8f2）を基本し、フォントは自前配信の Zen Maru Gothic を基本とし、未読込時は端末の丸ゴシック・Meiryo UI等へフォールバックする

## コメント共有

本番は確認済み二名のLINE識別子をサーバーのSecretに設定し、LINE内から非公開の保存・閲覧を開始する構成。公開設定は `paused: false`。未認証・許可以外の利用者はサーバーで拒否。緊急停止時は `paused: true` に戻す。本人限定テストは独立した接続設定と保存先を使用。二人の実機による相互保存確認は利用開始時に実施。

コメントはLINEで本人確認した二人だけで共有する。保存先とLIFFの設定が空の場合は投稿・取得を止め、画面に設定待ちを表示する。公開ページに実際のコメント、LINEユーザーID、秘密設定を追加しない。接続設定と確認状況は [コメント共有の設定手順](docs/comments-setup.md) を参照する。

ローカル検証は Node.js 24.13以降で `npm ci`、`npm test`、`npm run check` を実行する。テスト用の識別子とコメントは架空の値だけを使う。

## 二人の記録

本人だけの実機確認には、本番とは別のWorker・D1・LIFFを使う[本人限定の実機保存テスト](docs/owner-test-setup.md)を用意する。本番の二人必須条件は維持し、テストには架空データだけを使う。

背景移行や画面ロック時は未保存の入力をページのメモリ内に保護し、入力欄と保存済み記録を画面から消す。同じLINEアカウントをサーバーで再確認してから復元し、別のアカウントには復元しない。再読込・タブ終了・OSによるページ破棄では未保存の入力が失われるため、先に保存する。端末への自動保存や外部への下書き送信は行わない。

「二人の記録」で振り返り・売上と費用、やること、棚卸メモ、写真の照合、更新依頼を残す。金額や個人的な本文は認証済みAPIを通してD1へ保存し、公開HTML・Gitには書かない。空欄と0を区別する。棚卸メモで正本の更新シートを自動上書きしない。

出店・作品・売り場・やることの「コメントを書く」から対象別に保存する。保存後の「AIへの依頼に追加」で未対応の依頼へ残し、「依頼を選ぶ・コピー」へ進む。依頼一覧で「AIに渡す」を選び、内容を確認してからコピーする。外部AIへの貼り付けと送信は本人が行い、自動送信やボードの自動更新は行わない。「記録をファイル保存」で出すJSONは私的な金額・本文を含むため、公開リポジトリへ置かない。

公開前に `npm run privacy`、`npm run catalog`、`git diff --check` を実行する。`npm run smoke:deployed` は実トークンや実データを送らず、配備済みAPIの未認証アクセス拒否を確認する。画面だけでは利用開始を確認できないため、LINE設定後に二人の実機で確認する。

## 出店の準備

「出店を追加」で名称・日付・時刻・会場を非公開で登録する。既存出店は「準備 → 持参作品・使用ポップ」から選ぶ。選択は持参する種類だけを表し、在庫数や数量を推測しない。公開資料の名称・日時・会場や正本シートを上書きしない。既存の未分類記録はそのまま残す。

保存先には `backend/events-schema.sql` の追加テーブルが必要。導線・検証状況・配備手順は [出店の運用](docs/event-workflows.md) を参照する。

イベント写真は準備・当日・振り返りの各画面で折りたたまず一覧表示。登録済み写真と説明の対応を維持し、未登録の出店は未登録と表示。お知らせ文面4件は本人指定で画面から削除し、以前の版はGit履歴に保持。

出店一覧の「過去の出店」7件も折りたたまず表示し、既存の代表写真から各イベントの写真一覧へ進める。

ポップは作品と同じ写真上・名称下のカードで一覧表示。追加資料2件を含む全14件の画像・文字版プレビューは折りたたまず、詳細・文面とコメントは各カードから開く。
日本語変換中は確定前の保存・Escでの閉じる操作を抑止。同じアカウントの認証再確認では入力欄を再設定せず、保存失敗は入力欄の下に表示。実機のIMEと本番の相互保存は別途確認。

振り返り・売上は認証後に出店別の入力済み金額を合計。未分類・未入力・0円を区別し、各記録の「出店を紐付け／出店を変更」から明示的に関連付ける。日次・月次の重複や未記録分は自動補正しない。

コメント入力は共通のIME状態管理を使用。文字入力ごとにtextareaのdisabled・value・選択範囲を設定し直さず、変換終了と最後のinputの順序差を吸収。Android/Simeji実機での確認は自動テストと区別する。

コメントは未対応を先に表示し、対応済みは各一覧の下へまとめて保管。二人のどちらも「対応済みにする」「未対応へ戻す」を使用でき、本文を編集・削除できるのは投稿者だけ。本文を編集すると未対応へ戻る。状態はサーバーへ保存し、他の画面は再読込で取得。同時変更は版番号で検知し、未確認の変更を上書きしない。既存DBへの追加は `backend/comments-status-migration.sql` を列の存在確認後に一度だけ適用。

## コードの読み方と整形

`board.js` は公開ボードのナビ・対象別コメント、`comments-api.js` はLINE認証と通信、`ime.js` はネイティブ変換状態、`ui-core.js` はDOM生成と安全なID生成を担当。`board.css` は従来の基本スタイル、`studio.css` は画面配置、`typography.css` は書体を担当。詳細は [コード構成](docs/code-structure.md) を参照。

`npm run format` でJS/CSSを整形し、`npm run format:check` で確認。公開作品文面の空白を変えないためHTMLは自動整形しない。Prettierの版は固定。フォントのOFLライセンスは `assets/fonts/OFL-ZenMaruGothic.txt` に同梱。外部フォントサービスへの実行時通信は追加しない。
## 出店準備を先に見る

出店画面は公開資料の日程から次の出店を選び、準備・確認待ち・持参品へ直接進む。二人で追加した非公開出店は従来の一覧で確認する。準備件数はその出店へ明示的に紐付いた作業だけを集計し、未分類は自動で割り当てない。

作品の価格を詳細欄の外に表示。在庫は認証後の同名の最新棚卸メモを表示し、実在庫の確定値とは区別する。未登録と0を区別。次回持参の数量は現行保存形式にないため未登録と表示し、持参する種類の選択を数量に換算しない。

各作品・出店・ポップの未対応件数と最新コメントの短文は認証後だけ表示。背景移行・認証解除では消す。preparation.jsは表示専用で、DBの移行や自動更新を行わない。未保存の表示は安定した状態欄と親要素の印で切り替え、文字入力中のtextareaを再生成・上書きしない。

添付ポップ2件を追加資料として保管。おみくじ原画は既存の出店写真と旧価格表を残して別版表示、InstagramはPDF原本と縦横比を保持したプレビューを用意。原本PNG/PDFは無加工。図中の価格を作品の現在価格・在庫へ自動転記しない。既存12件の持参選択と保存済み選択は維持し、追加資料の選択保存は今回拡張しない。

追加写真は原本を非公開の作業フォルダーへ保持し、公開には長辺1080px以下・JPEG品質80・EXIF等のメタデータを除いた派生画像を使用。構図や本人の画像注記は変更しない。本人が人物の写り込みを含む掲載を承認した4枚も追加し、全44枚を出店28枚と作品・依頼・贈り物16枚へ整理。神戸は本人確認の2025年9月、愛知は2026年4月を表示し、他の未確認の開催回は推測しない。私的な売却・在庫メモ、顧客情報、添付元の識別情報は公開データへ入れない。既存写真・作品・イベントの削除や保存データの移行は行わない。
