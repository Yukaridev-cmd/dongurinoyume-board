# 本人限定の実機保存テスト

本番の二人用APIとは別のWorker・D1・LIFFアプリを使う。本番の二人必須の許可リスト、公開main、更新シートには変更を加えない。テスト用APIはサーバーでLINEトークンを検証し、事前確認した本人の識別子だけを許可する。先着登録や仮の二人目は使わない。

## 分離条件

- 本番用`DB`や`LINE_MEMBERS`が存在するテスト設定は拒否する。接続名は`TEST_DB`のみ
- 新しいD1にだけ`schema.sql`・`records-schema.sql`・`owner-test-marker.sql`を適用する。本番DBへ適用しない
- Workerは専用マーカーを持つDBだけを使い、テーブルやマーカーを自動作成しない
- 本人の識別子は`TEST_OWNER_LINE_ID`のSecretへ保存し、公開ファイルやGitへ記載しない
- ログ・トレース・追加プレビューURLを無効にする。認証トークンはURLに追加しない
- LIFFは別アプリにし、Full、openidのみ、友だち追加Off、Scan QRとModule modeはOff
- テスト画面には架空データ専用の帯を表示する。画像は既存公開分のみで、未承認ZIPや新写真を含めない

## コードの準備

`npm run build:owner-test`で、公開済み情報の画面ファイルと既存画像パスの一覧を`.wrangler/`に生成する。秘密値は含めない。`backend/owner-test.wrangler.toml.example`を手元専用の`backend/owner-test.wrangler.toml`へコピーし、新しいテストWorker・D1・LIFFの確認済み識別子を設定する。実ファイルはGit対象外。CLI利用のための新たな権限付与はこの手順に含めない。

本番の`backend/worker.js`の既定エントリーは引き続き二人必須。本人一人を許可する経路は`backend/owner-test.js`が生成する別エントリーだけで、リクエストや本番環境変数から切り替えられない。

## 本人のスマホで行う確認

1. テスト用として確認したLIFFリンクを、登録に使った本人のLINE内で開く
2. 先頭の「本人限定の実機保存テスト環境」と、本人のテスト用認証状態を確認する
3. 「二人の記録」を開き、項目名「実機保存テスト」、売上「0」、費用は空欄、本文「架空データ。再読込後の表示確認」と入力する
4. 「記録を保存」で保存済み表示を確認し、ページを再読込する。同じ記録、売上0円・費用未入力が表示されるか確認する
5. 本文を架空の別文へ編集して保存し、再読込後に更新内容を確認する
6. 別の未保存の架空下書きを入力し、LINEを一度離れて戻る。同じ本人の確認後に下書きが復元するか確認する

実際の売上・費用・在庫・個人的な振り返りは入力しない。テストデータを削除する場合は画面の確認を経る。本人のスマホ操作、LINE上の同意、認証済みの保存結果は実行前に成功扱いしない。奥様との相互確認はこの単独テストに含めない。

`scripts/check-owner-test.mjs`は`DONGURI_OWNER_TEST_ORIGIN`に指定したテスト専用オリジンへ、外枠の表示と匿名・偽トークンの拒否だけを確認する。有効なトークンや記録本文を送らず、記録を作成しない。
