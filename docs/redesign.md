# 二人で続けるための画面改修

## 入口を選ぶ

作品ボードは作品・出店準備の資料として残し、ホームから二人の記録へ進む。既存の作品写真を入口にも使い、クリーム色とMeiryo UIを維持。深い緑・茶・余白・丸みで画面全体を揃える。新しい写真や生成画像は追加しない。

作品一覧は名称・素材・公開メモで検索し、種類の絞り込みと組み合わせる。写真は一覧内で全体が見える表示へ変更。各作品のコメント入力は開閉式にまとめ、保存済みの件数を入口に表示する。既存のコメント対象名は変えない。

## 気づきを記録につなぐ

作品から棚卸メモへ進み、公開済みの作品名だけを引き継ぐ。受け取り側は作品カタログとの一致を確認する。在庫数や価格を写真から補わない。遷移だけでは保存しない。

二人の記録では未完了の作業・写真確認・更新依頼から、期限の近いものを先に最大3件表示する。期限のない項目は更新順に並べる。記録一覧には検索・未完了条件・更新順／期限順／項目名順の切り替えを設ける。検索結果なしと記録なしを区別する。

作業は一覧から完了にできる。元の版番号を付けて保存し、同時編集の競合をサーバーで拒否する。保存中の切り替えを止め、失敗時に完了表示へ進めない。保存応答が背景移行より遅れて到着しても、保護した入力を消さない。

スマホでは書き始め・保存済み一覧・更新依頼へ直接進む。PCでは記録一覧と入力欄を並べる。新規作成時には既存下書きの取消確認を通し、意図しない入力消失を防ぐ。

## 更新依頼を渡す

未対応の依頼文を画面内で確認してからコピーする。プレビューには保存済みの依頼だけを使い、HTMLとして解釈しない。認証解除・背景移行時にはプレビューと次の作業一覧も消す。外部AIへの通信・自動投稿は加えない。

## 保存と公開の境界

認証済みの保存・二名の許可リスト・版管理・下書き保護は既存の検証済み処理を使用する。画面改修に合わせたDB移行や権限追加は不要。本人テスト用のビルドにも共通スタイルを含める。本番APIは二名が未設定なら引き続き拒否する。

公開されるのは画面コードと既存の公開情報。金額・コメント・振り返り・本人識別子はコードへ入れない。今回の変更は作業ブランチまでとし、main・本番Worker・DB・元シート・新写真の公開へは反映しない。

## 検証

57件の自動テストが成功。新たに作品検索と種類フィルターの組み合わせ、公開作品名の引き継ぎリンク、期限順の作業表示、完了保存時の版番号、プレビューの非表示・消去、新規作成時の下書き保護を確認した。元の作品画像・価格・イベント・ナビゲーションの比較検査も成功した。入口へ再利用した既存写真のみ比較対象から除外し、従来の画像と代替テキストは全件比較する。

PC内のChromeで合成データによる作業追加と一覧表示を確認。390pxの記録画面と作品ホームを目視確認し、320px設定で両画面の表示幅とスクロール幅の一致を確認した。画面キャプチャのファイル保存はブラウザーのタイムアウトで未完了。実機の新版表示と二人の相互利用は未確認。

旧版については本人からコメント保存成功の報告を受領。新しい手動テストの繰り返しを求めず、既存の本人実機結果と自動検証を基に改修した。本番反映の条件は[二人用の運用を始める前の確認](release-checklist.md)を参照する。
