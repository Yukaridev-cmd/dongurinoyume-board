# 全コーナーのコメント実装規則

作品・出店・写真・ポップ・売り場の図や工夫・購入品・資料の作業・非公開記録など、独立した情報の対象ごとにコメントを書く導線を設ける。新規追加時も必須。ナビ、検索、絞り込み、保存ボタンなどの操作部品は情報コーナーとは区別する。一覧全体へのコメントで個々の対象を代替しない。写真と内容は初期表示を維持し、コメント入力だけを小さな開閉欄に収める。

## 公開ボードの追加方法

1. 内容のコンテナーへ固定の `data-comment-key` と `data-comment-label` を指定。キーはASCIIの小文字・数字・`:` `.` `_` `/` `-` で241文字以内。写真の例は `photo:photo-001`。ラベルは公開の作品名・説明だけを使用
2. `comment-coverage.js` が `DonguriBoardComments.register()` で共通エディターを登録。動的に追加する場合は `DonguriCommentCoverage.mount(container)` を一度呼ぶ。再呼び出しでも既存入力を作り直さない
3. 保存対象は `コーナー：` と固定キーを連結。表示名・開催月・順番・配置が変わってもキーを維持。同じ名前の別作品・別写真は別キーを使用。写真を別コーナーへ移動するときも同じ対象ならキーを保全
4. `npm run check:comments` と `npm test` を実行。対象の追加・再読込・未認証拒否・保存失敗・背景移行・同一ユーザーの下書き復元を確認

既存作品・ポップ・出店の保存キーは以前の名称を含む。これらは互換性のため完全一致で維持し、新しい固定キーへの自動移行はしない。既存写真・資料の新規コメントキーはHTMLへ明示的に固定済み。重複写真も一律に削除しない。

## 共通処理と非公開

`board.js` の共通エディターを使用し、独自の投稿処理・端末保存・外部送信を追加しない。`comments-api.js` とサーバーによる二人限定認証を必須とし、コメント本文は公開HTML・JSON・Git・URLへ書かない。未認証時は入力・保存を無効化。認証喪失や背景移行では入力と本文を隠し、サーバーで同一のviewerを再確認した場合だけメモリ内の下書きを復元。

文字入力でtextareaのvalue・disabled・選択範囲・フォーカスを再設定しない。`ime.js` の変換状態管理と保存時のガードを使用。保存失敗では本文と再送IDを保持。対応済みは削除せず下へ保管し、編集・再読込・競合確認の既存処理を使用。

非公開の記録・出店は `DonguriContextComments.button()` を使用。記録は `記録：UUID`、種類全体は従来の `記録ページ：種類`、追加出店は `出店：UUID` を維持。出店段階は `コーナー：phase:出店ID:prepare|day|review` として、公開資料側と準備ページで同じ対象に合わせる。未保存の新規記録にはIDの確定後に対象別導線を用意し、保存前はページ全体のコメントを使う。

## 網羅の確認

`scripts/check-comment-coverage.mjs` が実際のHTMLとナビ・段階生成後のDOMを読み、作品・ポップ・出店・写真・図・工夫・資料・作業・段階に各自の入力欄があることを確認。子要素のコメント欄を親の代用として数えない。ページ全体のコメントも別途確認。新しい種類の情報コーナーを作る場合は監査の必須セレクターとテストを同時に拡張。

監査はローカルで架空データのみを使用。本番コメントの取得や一括書き込みを網羅テストに使わない。実機LINE/Simejiの確認は自動検証と区別して報告。
