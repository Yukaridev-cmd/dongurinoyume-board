# 二人用の運用を始める前の確認

2026年11月17日：二名のLINE識別子照合・妻のTester参加・本番Secret設定・追加スキーマ・未認証拒否を確認済み。二人の実機での相互保存は未検証。

本人限定テスト環境での確認結果と、本番の二人用環境の確認を分けて記録する。テスト用Worker・DB・LIFFを本番へ転用せず、架空データを本番へ移さない。公開mainへの反映は配備内容を本人が確認してから行う。

## 本人単独で確認した範囲

- LINE実機からテスト専用DBへの新規保存
- 保存済み記録の編集、版更新、変更前の履歴保全
- 費用の未入力をnullとして保持し、0円と区別する保存
- 再読込後の表示と、背景移行後に文字が戻ること（本人の実施・完了報告）
- 記録を保存した後も匿名・偽トークン・別オリジンを拒否し、記録本文を返さないこと

自動テストは両メンバー・第三者・失効・競合などの応答を模擬する。実際の二人による相互確認や、すべての端末条件を確認した結果とは扱わない。

## 二人で確認する範囲

1. 同じLINEプロバイダーで各本人の識別子を確認する。奥様の参加は本人の都合を待ち、先着登録・仮の二人目・表示名による代用は行わない
2. 開発中チャネルで必要な場合は、確認した宛先へTesterとして招待する。管理者やMember権限を追加しない。招待送信や新しい同意は対象を確認してから行う
3. 本番WorkerのSecretへ確認済み二名だけの許可リストを登録する。LINEチャネルIDと本番LIFFの対応、ログ・トレース・追加プレビューURLの無効を確認する
4. 二人がそれぞれ投稿・再読込し、相手の記録を確認する。振り返りとコメントは本人だけが編集・削除でき、共有タスクは二人が更新できることを確認する
5. 同時編集で古い版を上書きできないこと、第三者が読み書きできないこと、認証解除や別利用者で下書きが見えないことを確認する

招待メールは受信できるアドレスを使い、LINE登録メールとの一致は条件にしない。招待を受諾したときにログイン中の開発者アカウントへ権限が付くため、妻本人のLINEに紐づくアカウントで受諾する。TesterでもBasic settingsのYour user IDを確認可能。表示名や検索用LINE IDで代用せず、同じチャネルで確認した識別子を秘密設定へ登録する。[LINE公式のロール管理](https://developers.line.biz/en/docs/line-developers-console/managing-roles/)

既存本番DBへの追加は`backend/events-schema.sql`だけを使い、テスト環境の初期化SQLやマーカーを流さない。適用前後で既存テーブルの件数を比較し、追加テーブル2件と履歴トリガーを確認する。既存レコードの本文や金額を配備確認のために読み取らない。

## 公開mainへ反映する直前

- 本番の配備エントリーは`backend/worker.js`、許可人数は二名。本人テスト用のエントリー・Secret・TEST_DBを使わない
- 本番DBとテストDBのUUIDが異なることを確認する。スキーマを変更する場合は対象DBを再確認し、テスト専用マーカーを本番へ作らない
- viewer対応のWorkerとクライアントを揃える。公開設定には本番用LIFF IDとAPIオリジンだけを記載する
- `.env`、Secret、識別子、認証トークン、DB、実額、実際のコメントをファイルやGit全履歴に含めない
- 新しい写真は対象と公開範囲を確認したものだけにする。ZIP一括追加や、家族・会話・決済画面の混入を防ぐ
- 元の画像・価格条件・イベント日時を保全し、未入力・未確認値を推測しない。写真点数を在庫と扱わない
- 必要なテスト・秘密情報検査・差分検査と、配備対象の本人確認を完了する。作業ブランチの送信をmain反映の承認へ読み替えない

運用開始後のバックアップ・保存期間・復旧手順、履歴の確認方法、削除済みデータの扱いは二人で決める。外部AIへの自動送信は実装せず、送信先と内容を確認したコピー・書き出しを使う。
