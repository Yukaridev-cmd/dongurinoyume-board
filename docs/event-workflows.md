# 出店を中心にした4分類

主要ナビを出店／作品・在庫／売り場／やることへ変更。スマホでは画面下部に固定し、文字と共通SVGを併記。背景のクリーム色、Meiryo UI、既存写真・価格条件・イベント情報を維持する。

| 場所 | 実装した内容 |
| --- | --- |
| 出店 | 今後2件・過去7件を維持。準備・当日・振り返りの3切替。新しい出店は非公開で追加 |
| 出店の準備 | 27作品・12ポップから持参する種類を選択。検索・選択件数・準備メモ・編集保存 |
| 作品・在庫 | スマホで2列の写真一覧。価格と名称を常時表示し、詳細・棚卸リンク・相談はカード内で開く |
| 売り場 | ポップとブース・道具を横の切替で表示。同じ元データとコメント欄を移動し、複製しない。資料へも1操作 |
| やること | 非公開の作業一覧へ直通。全件・未分類・特定出店で絞り込み、元の1記録を編集・完了 |
| 売上・振り返り | 出店から関連する非公開記録へ。売上・費用と未入力／0の区別を維持 |
| 相談・AI依頼 | 相談ボタンを固定。AI依頼への直通と、コメントから明示的に依頼へ保存する仕組みを維持 |

## 出店との関連付け

非公開記録のJSONに任意の `eventId` を追加。既存9出店の識別子・保存済みの新規出店UUID・空文字だけをサーバーで許可する。元の記録に項目がない場合は未分類のまま残し、名前・日付から推測しない。

出店から追加する場合は、選択した出店を入力フォームに明示する。未分類へ変更して保存も可能。既存記録は編集時に出店を選んで保存するまで関連付けない。関連付け変更は既存の版管理・編集権限・履歴保全の対象とする。

出店の絞り込みは一覧表示だけを変える。AI依頼の確認・コピーも選択した範囲に合わせ、条件変更時は前のプレビューを閉じる。認証前や認証喪失時は私的本文・金額・下書きを表示しない。外部AIへ自動送信しない。

## 操作と検証

認証済みの状態を前提に、入力文字数・保存ボタン・ログイン操作を除いて数える。

| 目的 | 操作数・経路 |
| --- | --- |
| 出店の準備作業を見る | 2：出店を開く → 準備すること |
| 出店の売上を記入する | 3：出店を開く → 当日 → 売上・費用を記録。認証後に入力フォームを直接開く |
| 全作業を確認する | 1：固定ナビのやること |
| ポップを見る | 1で売り場の一覧、2で対象の画像・価格・印刷内容 |
| ブースを見る | 2：売り場 → ブース・道具 |
| 作品の棚卸へ | 3：作品・在庫 → 対象の詳細 → 棚卸メモのリンク |
| 新しい出店を作る | 1：出店を追加 → 基本情報を記入 → 保存 |
| 既存出店の持参作品を選ぶ | 3：出店を開く → 持参作品・使用ポップ → 持参作品タブ |
| 追加した出店の持参品を編集 | 3：追加済み出店を開く → 持参品・出店情報を編集 → 持参作品タブ |

前版の4分類実装時は、390px設定で今後2出店のカード下端584px、下部ナビは4等分・各高さ52px。320px設定で売り場の切替は各91×44px、作品カードは2列・各幅137px。横溢れなし。以下の新規出店・切替安定化を含む新版の実画面は再確認が必要。

PC内の合成データで、出店を選んだ売上0円・費用空欄の保存、関連出店の表示、未分類フィルターとの分離を確認。元の画像・価格・イベント本文と旧資料の一致、未分類の保全、出店指定の検証・解除・履歴、下書き保護、認証喪失、主要導線を自動テストする。

前版では67件の自動テスト、本人限定テストへの配備、12配信ファイルの一致、匿名・偽造アクセス拒否17項目、本番未設定時の拒否9項目を確認。テストDBの件数・版合計・履歴件数は配備前後で一致。これは新規出店機能の配備を示す結果ではない。

前版の配備画面の390px設定では今後2件のカード下端617px、固定ナビ上端783px。クリスマスの準備操作の下端424px、3切替は各114×44px。テスト環境の案内を含め主要操作が初期画面内に収まることを確認済み。

## 新規出店・持参品の保存

「出店を追加」から名前・日付・時刻・会場を登録する。日付などの未入力を許可し、推測で埋めない。新しい出店の情報は認証済みAPIからのみ取得し、公開HTML・Git・更新シートへ転記しない。既存出店は公開資料の識別子を使って準備内容だけを保存し、名称・日時・会場を書き換えない。

持参作品・使用ポップはそれぞれタブを開いて選び、まとめて保存する。選択は種類を示し、写真点数や選択件数を在庫数と扱わない。数量は未管理。

保存には新しい `event_plans`・`event_plan_history` を使う。明示保存と版番号による競合検知を行い、変更前の版を履歴に保管。通信結果が不明な再試行は同じ識別子・版を使い、重複作成を防ぐ。出店削除UIは設けない。既存記録・コメントのテーブルは移行・削除しない。

## 切替と下書きの保護

主要タブごとに同一ページ内のスクロール位置を記憶して復帰する。出店内・売り場・選択フォームの切替では押した操作欄の位置を補正する。見出し・ナビ・認証状態・短い通知の最小高さを揃え、スクロールバーの幅とSVG描画前の場所を確保。本文全体に固定高さを設けず、内容に応じた自然な長さを維持する。

同じ認証済み本人の再確認では、追加出店一覧を先に空にしない。変更のないカードは置き換えず、フォーカスを維持する。編集中の出店フォームも再認証通知だけで再描画しない。

背景移行・認証喪失では私的な出店名、会場、選択、メモ、記録の選択肢を消去する。下書きはページメモリ内で保護し、同じアカウントのサーバー確認後にだけ復元。端末保存や外部AIへの自動送信は行わない。

## 新版の検証・配備状況

PC内の自動テスト80件が成功。合成データで新規作成・明示選択・再読込・空選択への編集・再試行・履歴・競合検知を検証。SQLiteファイルを開き直しても選択を保持する。本人限定APIの第三者拒否、二人用APIの認証、DOMへの安全な文字描画、背景移行・別アカウントへの下書き非表示、未分類・0円・空欄・元資料の保全を含む。

新版はPC内で実装済み。ブラウザー接続が時間切れになり、CLIも未ログインのため、追加テーブルの適用・Worker配備・実ブラウザーでの320px／390px確認は未実施。テスト環境には4分類の前版が残る。DOMテストを実機画面の検証結果とは扱わない。

再接続後は本人限定D1へ `backend/events-schema.sql` だけを追加。旧テーブルの件数・版合計を比較してから新版を配備し、公開外枠17ファイルの一致、未認証拒否、狭い画面の切替位置、架空データの認証済み保存を確認する。公開main・本番・奥様の登録は変更しない。

## 残る範囲

- 新しい出店・選択保存のLINE実通信と、奥様との共同利用は未検証。
- スマホ実画面での高さ・配置・ちらつきの最終調整は、接続復旧後に確認する。
