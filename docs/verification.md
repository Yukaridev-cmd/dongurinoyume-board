## 背景移行と未保存入力の修正（ローカルのみ）

背景移行・画面ロック・ページキャッシュ移動は認証失効と区別し、未保存の記録・金額・新規コメント・編集をメモリ内に退避する。画面と入力欄は空にし、同じ利用者の再認証後に復元する。表示名ではなく、サーバーで検証したLINE識別子とチャネルから生成する不透明な`viewer`値で紐付ける。LINE識別子そのものはクライアントへ返さない。トークン変更時は再確認するまで送信を止める。

通信断のみでは表示中の入力を消さない。401・403では入力を保護して画面から消す。保存中に離れた場合は同じ新規登録IDで再試行し、編集の版番号は元の値を保つ。再接続によって古い編集を最新の版へ自動的に載せ替えない。再読込・タブ終了時はブラウザの離脱確認を要求するが、LINEやOSによる強制終了では保証できない。永続的な下書き保存は含まない。

`npm test`は42件成功。実クライアントと記録画面を組み合わせ、背景移行、同一表示名の別利用者、通信断、401・403（JSON以外の拒否応答を含む）、遅延応答、保存中の復帰、元の版による競合、未送信コメント欄の消去、トークン変更時の送信停止を検証した。localStorage・sessionStorageへの書き込みと自動POSTがないことも確認した。

この修正は未公開・未配備。`/session`へ`viewer`を追加するWorkerとクライアントを揃えて配備する必要がある。旧Workerとの組み合わせは共有機能を閉じたままにする。下記の配備済みWorkerのハッシュは修正前の値で、今回のローカル修正を含まない。実LINE・実機ロック・OSによるプロセス破棄・認証済み本番D1通信は未検証。

## 日本語入力の互換性修正（2026年11月17日）

対象別コメント欄が各inputイベントでtextarea.disabledを再代入していた経路を除去。input中は汚れた状態の管理だけを行い、editorのvalue・属性・選択範囲・フォーカスを変更しない。共通ime.jsはWeakMapで状態を保持し、compositionstartの欠落、beforeinput/inputのisComposing、compositionendと最後のinputの前後差、focusoutを扱う。変換直後の最終inputが終わるまで保存・取消によるeditorの破棄を待つ。認証喪失・背景移行時の非表示は遅らせない。

[W3C Input Events](https://w3c.github.io/input-events/)と[Android InputConnection](https://developer.android.com/reference/android/view/inputmethod/InputConnection)を参照。実機原因がSimeji固有と確認したものではない。自動テストではイベント順序とDOM不変を検証し、PCブラウザーでは合成データの先頭文字・フォーカス・保存を確認。Android LINE WebViewとSimejiの実IME・端末版による入力は未検証。

公開HTMLは入力関連JSに版番号を付け、旧キャッシュによる修正前スクリプトの混在を防ぐ。DB・二名の許可・保存済みデータを変更しない。
